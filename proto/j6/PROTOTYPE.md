# J-6 Explorer — UI prototype

**Status:** prototype v0.1 · 2026-10-05
**Files:** `explore.svg`, `find.svg` (screens) · `j6.mjs` (engine + data) · `j6.test.mjs` (12 checks) · `build-prototype.mjs` (draws the screens from the engine)
**Now in the repository (2026-10-06):** the engine is `j6/j6.mjs`, the tests `tests/j6.test.mjs`, and the scenarios are in `sketchpad.feature`. D-J01–D-J06 are `D-079`–`D-084` in `DESIGN.md`. This file is kept as the record of what was agreed.
**Source data:** Roland J-6 Owner's Manual v1.02, *Chord Set List*, https://static.roland.com/manuals/J-6_manual_v102/eng/28645807.html

This is a design prototype for the J-6 Chord Explorer brief. It is not part of `sketchpad.jsx` yet, so Sketchpad's `check-done` gates don't run on it. It follows the same Definition of Done by hand: decisions, scenarios, tests named after scenarios, and code. When it is merged into Sketchpad, the decisions get `D-nnn` numbers, the use cases `UC-nn`, and the scenarios move into `SCENARIOS.md`.

## 1. What the screens show

**Explore** (J-6 → theory). Set 54 (House). The user has tapped C, C♯, G, D♯ in the order they played them on the hardware.

- The virtual J-6 shows **what every pad plays**, printed on the pad. This is the main thing the hardware can't show you.
- Played pads are numbered in order. The latest is bright amber; the earlier ones are dim amber.
- **Now:** Fmaj7, IVmaj7 in C major, notes F A C E with their degrees, and the J-6's actual voicing (F3 A3 C4 E4).
- **Piano** lights the actual voicing in its real octave, not an idealized chord.
- **Key:** C major, all 4 chords fit. The runner-up (G major, 3 of 4) is shown so the confidence is honest.
- **Progression:** Cmaj7 › Em7 › Am7 › Fmaj7 / Imaj7 iii7 vi7 IVmaj7, each with its J-6 key. Undo, Clear and Play.
- Filter, envelope, delay and reverb appear as dim knobs labelled "display only" (brief §10).

**Find** (theory → J-6). Query `Dm7 G7 Cmaj7 Am7`, Musical mode, KEY transpose on.

- **Best match: Set 47 at KEY −3, 4/4 exact.** No set in this sample contains ii–V–I–vi untransposed, but set 47's Fm7, A♯7, D♯maj7 and Cm7 become exactly Dm7, G7, Cmaj7 and Am7 three semitones down.
- The pads show what each key plays **at KEY −3**. The keys to press are numbered 1–4; dashed pads play the same chord (D♯ or F♯ both give Dm7).
- Three plain steps for the hardware: select the set, set KEY, play the keys.
- **Other sets** with the reason they rank lower: set 29 (88%: Cmaj7/E is an inversion, Am stands in for Am7), set 54 (75%: no G7).

Every chord name, voicing, numeral and percentage on both screens is computed by `j6.mjs`. `build-prototype.mjs` draws the SVGs from the engine (`D-J06`), so the picture can't disagree with the tests.

## 2. Decisions

### D-J01 — Show musician spelling; keep the manual label as a secondary line
**Context:** The manual writes `A#M7`, `D#M7`, `F#FM7` (a typo in set 19).
**Decision:** The app shows `B♭maj7`. "Manual says A#M7" appears under the chord, so the user can match it to the printed chart.
**Gap:** Spelling is flats-for-black-keys for now, so F♯m7 would show as G♭m7. Key-aware spelling comes from Sketchpad's theory layer when the engines merge.

### D-J02 — Match on the J-6's actual notes, not on chord names
**Context:** The J-6 is 4-voice. Its "G7" in set 29 is G B F G, with no 5th.
**Decision:** A voicing counts as its chord if the root sounds and every note belongs to the chord. Missing tones are allowed. The piano lights the real voicing.

### D-J03 — Transposition is part of the search
**Context:** None of the three sampled sets contains Dm7 G7 Cmaj7 Am7 untransposed. Set 47 at KEY −3 contains it exactly.
**Decision:** Search tries every KEY value by default, and the result always says which KEY to set. Ties go to the smaller transposition.
**Assumption:** The KEY range is taken as −6…+5 until it is checked on the device (`@manual` below).

### D-J04 — The manual's data is validated before use
**Context:** Set 59 (EDM) fails validation on **all 12 keys**. Its printed voicings are near-copies of set 60's: "C6" is printed as F♯ B E D♯, which has no C. Set 19 also has a typo in a label, and set 43 lists F3 twice in one chord.
**Decision:** Every set runs through `validateSet` before search. A set that fails is never recommended. This is the strongest argument for capturing voicings from the device over MIDI rather than trusting the PDF.

### D-J05 — The 8th lower pad is the high C
**Context:** The J-6 has 8 lower and 5 upper pads; the chord list has 12 columns.
**Decision (assumption):** The high C plays the C chord. It's drawn that way, and it's dashed when C is in the answer. To verify on the device.

### D-J06 — Screens are drawn by code from the engine
**Decision:** The prototype SVGs are generated by `build-prototype.mjs`, never hand-edited. A wrong chord on screen is then a wrong engine result, which the tests can catch.

## 3. Scenarios

    And the manual label reads "FM7"

  @auto @D-J03
  Scenario: Dm7 G7 Cmaj7 Am7 finds set 47 at KEY −3 with four exact matches
    Given sets 29, 47 and 54, musical mode, transpose allowed
    When the user searches "Dm7 G7 Cmaj7 Am7"
    Then the best match is set 47 at KEY −3 scoring 100%
    And Dm7 is on D♯ or F♯, G7 on A, Cmaj7 on C♯ or E, Am7 on C

  @auto
  Scenario: Musical search counts an inversion and a missing seventh as near matches
    Given set 29 without transpose
    When the user searches "Dm7 G7 Cmaj7 Am7"

    And the score is 87.5%

  @auto
  Scenario: A chord with the wrong third is never a musical match
    Then Gm7 is not a match for G7
    And A is not a match for Am7

  @auto
  Scenario: Exact search without transpose ranks set 54 first at 75%
    Given sets 29, 47 and 54, exact mode, no transpose
    Then the ranking is set 54 (75%), set 29 (50%), set 47 (25%)

  @auto @D-J01
  Scenario: Chord symbols are read the way musicians type them
    Then "Cmaj7", "CM7", "Bbmaj7", "A#M7", "CM7/E" and "C-7" are all understood

  @manual @D-J03

    Given the J-6 on set 47

    Given any chord set

## 5. Open questions

1. **KEY range and direction** on the device (`D-J03`).
2. **High C pad** behaviour (`D-J05`).
3. **Data source:** transcribe 100 sets from the manual (now known to contain errors), or capture them over MIDI? The validator works on either.
4. **Musical substitutions** need more qualities (9, 11, 13, sus, add9) before "Cmaj9 for Cmaj7" can work. The manual uses roughly 80 distinct chord spellings.
5. **One app or two:** these screens assume a separate J-6 app with Explore/Find tabs. As a Sketchpad screen, the Now / Piano / Key cards would be Sketchpad's existing panels.
